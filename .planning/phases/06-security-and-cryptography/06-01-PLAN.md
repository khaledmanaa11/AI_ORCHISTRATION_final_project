    names, mirrors `HandshakeKey`/`HintKey`). Three functions:
    - `build_commit_payload(*, state: dict, move: dict, intent: str, nonce: str) -> dict` — the
      ONE dict-assembly function (D-59). Validates `state`/`move` are dicts, `intent` is exactly
      `Intent.TRUTH.value` or `Intent.LIE.value` (Pitfall 3 — reject a bool loudly), `nonce` is a
      non-empty str. Raises TypeError/ValueError, never silently coerces. `move`'s INTERNAL shape
      is opaque to this function (06-02 populates it with the composite `{"move": ..., "barrier":
      ... | None}` dict per revised D-59/D-66 — a cop turn that places a barrier instead of
      moving encodes 'move' as a "stay" token, mirroring `CopAction.destination()`'s own
      "unchanged when placing" semantics); this module never imports `move_payload` or validates
      that internal shape — say so in the docstring so a future reader does not add a second,
      narrower validation that would silently reject a legal barrier-only turn.
    - `commit(state: dict, move: dict, intent: str) -> tuple[str, str]` — generates
      `nonce = secrets.token_hex(16)` (SEC-04, rule 18), calls `build_commit_payload`, hashes via
      `hashlib.sha256(canonical_json(payload).encode("utf-8")).hexdigest()`, returns
      `(h_commit, nonce)`.
    - `verify_reveal(h_commit: str, *, state: dict, move: dict, intent: str, nonce: str) -> bool`
      — rebuilds the payload via `build_commit_payload` (same function, never a second builder),
      recomputes the hash the same way, compares via `config_hash.digests_match`.

    `state_record.py` — `StateRecordKey(str, Enum)`: `GAME_ID`, `TURN`, `ROLE`, `POSITION`,
    `BARRIERS_REMAINING`. `build_state_record(*, game_id: str, turn: int, role: str, position:
    tuple[int, int], barriers_remaining: int) -> dict` returns exactly `{"game_id": game_id,
    "turn": turn, "role": role, "position": {"row": position[0], "col": position[1]},
    "barriers_remaining": barriers_remaining}` (D-60's fixed field set — nothing added, nothing
