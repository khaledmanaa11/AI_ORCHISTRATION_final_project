# Phase 6 Plan 5: Gap closure — audit turn-binding + verdict durability

Closes the two gaps `/gsd:verify-work 6` found and diagnosed in
[`06-UAT.md`](06-UAT.md). Both were reproduced against the shipped code with paired controls
before this plan was written; neither is speculative.

## Why this is a plan and not a patch

Gap 1 is the third instance of the same failure mode in this phase (after the dead
`verify_declaration` and the vacuous `all_matched([])`), and it defeats the fix for the second
one. The pattern is: **an enforcement check whose inputs the adversary supplies.** The fix has
to remove the adversary from the input, not add another check on top of the same untrusted
value.

## The design decision, and why

Two options were on the table:

| Option | Effect | Risk |
|---|---|---|
| A. Validate inbound `envelope.turn` against local state, reject on mismatch | Closes it at the source | A false accusation if any legitimate skew exists — a rules-16/22-grade error, and exactly the mistake 06-03 made once already (Step-0 digest equality between two roles that can never hash equal) |
| B. Key the audit on locally-authoritative turn state | Closes both exploit paths; cannot break an honest game, because it stops reading the peer's number at all | None to gameplay |

**B is the primary fix**, because it is the one that cannot produce a false accusation. It also
fails closed in the other direction for free: a peer that publishes its FINAL_REVEAL records
under skewed turn numbers now finds those turns absent from `observed_commits` (→ "no observed
commit") and leaves the real turns unreported (→ the coverage check names them).

A is treated as an optional second layer, and is kept **only if measurement shows honest play
never trips it** (see must_haves: honesty). Keying on local truth already closes the hole, so
layer A must earn its place rather than being assumed.

## What is deliberately NOT touched

`src/pursuit/security/audit.py`. Its three ordered checks, the trailing-commit exemption, and
the rule-36 coverage check are all *correct* — they were being fed attacker-controlled keys.
Changing the audit logic to compensate would weaken a correct function to work around a
problem one layer below it.
