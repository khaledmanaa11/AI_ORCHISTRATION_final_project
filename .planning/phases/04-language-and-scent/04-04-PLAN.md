  <action>
    A `Direction` enum (`NORTH`, `SOUTH`, `EAST`, `WEST`, `STAY`) whose values are the wire words,
    plus the cop's barrier form — a barrier placement names the cell **relative to the cop**
    (its own cell or one orthogonal neighbour), so the same vocabulary covers it with an action
    kind alongside the direction.

    Three functions:
    - `encode(pre, post, kind) -> payload dict` — our outgoing shape. No integers naming a cell.
    - `decode(payload, pre_cell, rules) -> Action` — accepts **either** the direction shape or
      the legacy `{"x","y"}` shape (D-53). The legacy branch converts the coordinate back into a
      direction and then validates identically, so exactly one validation path exists.
    - `is_legal(pre, action, state, rules) -> bool` — the resolved action must be in the role's
      legal set from `sdk/actions.py`. **Do not reimplement the rules here**; import them.

    The origin convention matters: `north` must agree with `game_params.json`'s `origin`
    (top-left) so that both peers walk the board the same way. Derive the vector from the loaded
    origin, do not assume it.

    An illegal or unparseable payload returns a rejection the caller turns into a **technical
    loss for the sender** (rules 13/14) — it is never coerced to `STAY` and never raises out of
    the handler.
  </action>
  <verify>
    Round-trip property test: for every legal `(pre, post)` pair on a 7×7 board,
    `decode(encode(pre, post), pre)` recovers `post`. A legacy `{"x","y"}` payload for the same
    move decodes to the same action. A diagonal, an off-board step and a garbage string each
    produce a rejection naming the reason, with no exception escaping. Flipping `origin` flips
    the sense of `north` in the resolved cell.
  </verify>
