  <action>
    `shared/inference.py` holds a frozen `Inference`: an optional named region, an optional list
    of implicated cells, an optional direction of motion, a confidence in `[0, 1]`, and the raw
    text it came from (for the event log and the replay viewer). Plus the module-level
    `NO_EVIDENCE` singleton — confidence 0, nothing implicated.

    It lives in `shared/` because both `services/llm/` and `strategy/` need it and neither may
    import the other. Do not put it in `services/`.

    `decode_schema.py` holds the JSON schema sent as `output_config.format` **and** a
    `validate(obj) -> Inference | None` that re-checks the response. Re-validating is not
    paranoia: a schema on the request constrains the model, and the only thing that guarantees
    our types is our own check. Reject on: unknown keys, confidence out of range, a cell outside
    the board, a direction outside the vocabulary, both `region` and `cells` absent while
    confidence is above zero.

    Keep the schema small. Structured-output schemas do not support numeric bounds, so range
    checks live in `validate`, not in the schema — note that in a comment so nobody "fixes" it
    by adding a `minimum` that the API will reject.
  </action>
  <verify>
    A well-formed object validates into an `Inference`. Each malformed case above returns `None`.
    `NO_EVIDENCE` has confidence 0 and implicates nothing. The schema round-trips through
    `json.dumps` and contains no unsupported keyword.
  </verify>
  <done>The contract exists in one place, and it is checked on our side of the wire.</done>
</task>

  <action>
    `decode_hint(text, context) -> Inference`. One entry point, no exceptions out.

    Order: reject trivially bad input locally before spending a token (empty, whitespace, absurdly
    long) → build the prompt → call the provider with the schema → `validate` the response →
    return the `Inference`. **Every** other path returns `NO_EVIDENCE`: any `LlmFailure` reason,
    a schema violation, a parse error, an unavailable provider.

    Log at debug with the reason so 04-14 can report how often decoding actually succeeded — a
    silent no-evidence path that fails 100% of the time would otherwise look identical to a
    truthful opponent.

    The `template` provider cannot decode. Under it, `decode_hint` returns `NO_EVIDENCE`
    immediately without a call. That is the honest behaviour and it means the belief map runs on
    scent alone in the zero-token configuration — say so in the docstring, because it is a real
    capability difference between the two provider modes, not a bug.
  </action>
