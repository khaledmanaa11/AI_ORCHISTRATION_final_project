    (a) Relax the receive-side window in `record_hint`:
        `if turn < ctx.state.turn - _HINT_LOOKBACK_TURNS: return`
        with `_HINT_LOOKBACK_TURNS = 1` as a NAMED module constant carrying its derivation
        in a `#` comment: a hint for turn N is emitted at the TAIL of turn N — after
        REVEAL(N) and an LLM compose — so it is first pulled off the queue when the receiver
        has already resolved to N+1. One turn of lookback is the MINIMUM that makes the
        channel deliverable at all; it is structural, like `agent_audit_wiring`'s own
        `_DECLARE_RETRIES`, and is explicitly **not** a PARAMETERS.md value and **not** a
        config key. A hint older than that is genuinely stale and still drops — the rule
        keeps real content, which is what lets its test be re-specified rather than deleted.

    (b) Freshness guard, which the window makes necessary. Today's unconditional overwrite
        was safe only because at most one turn was ever admissible; with lookback, two hints
        from the same sender can both pass the guard and an out-of-order OLDER one would
        clobber a fresher one in `ctx.incoming_hints` — silently feeding stale evidence to
        the belief update. Overwrite only when the incoming `turn` is at least as new as the
        stored payload's own stamp.

        **Read that stamp DEFENSIVELY. This is the part that can kill a game.** The stored
        payload is peer data: `validate_hint_payload` runs only inside `build_hint` on the
        SEND path, and `Envelope.from_dict` checks nothing but `isinstance(payload, dict)`.
        So `stored[HintKey.TURN.value]` may be missing, `None`, `"3"` or a bool, and a bare
        `turn >= stored[...]` raises `TypeError` inside `record_hint` — which NO call site
        catches (`await_opponent_turn` catches only `HintProtocolError`), so it escapes
        `run_turn_loop` and ends the game. That is precisely the failure
        `turn_buffer.py:60-71` documents at length: 04-12's whole deviation exists because
        raising here turns ordinary jitter into a forfeit caused by a hint, which this
        plan's own must_haves rule out. Use `stored.get(HintKey.TURN.value)` and treat
        anything that is not a plain `int` (missing, None, str, bool — bool is not a plain
        int, mirroring `envelope._require_non_bool_int`) as "no usable stamp -> replace".

        One consequence, stated rather than discovered later: the stamp is peer-controlled,
        so a peer can make its own hint sticky for the rest of the window by stamping a huge
        turn. Self-inflicted on a best-effort channel whose content is a CLAIM anyway, and
        the lookback window still expires it — acceptable, but say so in the docstring.

        A stored payload with no usable stamp is simply replaced, so the existing
        same-turn-overwrite test at :30 is unaffected. Apply the same rule to both buffers.

    (c) In `turn_actions.take_my_turn`'s responder branch, stamp the outgoing hint with
        `pending.turn` — the turn the action was actually committed and revealed under — not
        `ctx.state.turn`, which `maybe_resolve` has already advanced. `pending.turn` is
        already in scope and is already what `reveal_pending` sends under.

    (d) G1's stagger half, both branches: skip `compose_and_send_hint` entirely when
        `maybe_resolve` returned an outcome — the turn is over, the opponent will never play
        another, and composing costs an LLM round trip (17.4 s, measured). On the initiator
        branch `maybe_resolve` is a no-op so this is behaviour-neutral; on the responder
        branch it removes the tail.
