# 05-13 — the audit survives long enough to be honest

**Gap (verify-work Round 2, 2026-08-16, HEAD `bcc04bf`).** 05-04 shipped the right fix and
wired it correctly: `run_final_audit(board_outcome=)` is passed from `agent_entrypoint.py:110`,
and on a failed outbound push with a board outcome standing it calls the non-accusatory
`record_audit_incomplete` and falls through to receive-and-audit. Verified present. **But
the branch cannot execute for the timeout class of failure**, which is the class the tunnel
actually produces.

This is the same failure shape as the pre-05-11 `ensure_connected()` case — the code
exists, the caller exists, and the path still cannot run in the deployed configuration.
There it was "no caller"; here it is "killed before it is reached".

**Fix shape (three tasks).**

1. `agent_audit_exchange.py` — touch the watchdog once per bounded attempt in
   `push_final_reveal` and `receive_final_reveal`, mirroring `turn_commit_send.py:52`.
   Liveness stays honest: each touch marks a real attempt starting, not a heartbeat on a
   dead loop, so a genuinely frozen agent is still killed at `watchdog_threshold`. State in
   the docstring why the audit needs this and the turn loop already had it.
2. `agent_audit_wiring.py` — extend 05-04's rule to the RECEIVE leg: when a board outcome
   already stands, a failed receive records `audit_incomplete` (reason naming OUR failed
   receive, never the peer) and leaves the board outcome standing. `record_technical_loss`
   stays reserved for a real `AUDIT_HASH_MISMATCH` or a turn loop that never resolved.
3. Tests — give `_fakes_agent.make_ctx` an opt-in real watchdog driven by an INJECTED
   clock, then add the case that was previously inexpressible: a push ladder that outlives
   `watchdog_threshold` still reaches `audit_incomplete`, still writes an `audit_verdict`,
   and still emits no `technical_win`. Add the mirrored receive-leg case. Keep all three
   existing paired fairness controls green, and record a revert probe for each new case
   (remove the touch -> the slow case dies on `watchdog_incident`).

**Line budget** (measured at HEAD `bcc04bf`; `scripts/check_line_limit.sh` is authoritative
and currently exits 0 tree-wide): `agent_audit_exchange.py` 101/150, `agent_audit_wiring.py`
134/150, `audit.py` 142/150. The touches here are small — a touch call per bounded attempt
and one branch — so no split is expected; re-measure before each commit and split a sibling
rather than compressing if that changes.

**Non-goals.** No change to `watchdog_threshold` or any Table-19 value (rule 1). No move of
`linger_for_peer` into the audit — it stays in the `finally` where 05-04 put it for the
documented reason. No redesign of the single-queue FINAL_REVEAL delivery path (a real
residual, recorded separately and out of scope here). No touching `peer_runtime.stop()`.
