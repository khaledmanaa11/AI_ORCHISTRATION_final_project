# 05-15 — the declaration story, settled and written down

**Gap (verify-work Round 2, 2026-08-16).** The adversarial pass found that
`declare_truthfully()` — whose docstring calls it "the one constructor for a barrier or
capture declaration" for rules 15/16 and 21/22 — has **zero production callers**, while in
both live games the police placed a barrier and captured, and every utterance it sent was an
`intent: lie` LOCATION bluff. That looked like a disqualification-class rules gap.

**It is not.** Checked against the book extract before touching anything: the barrier is
declared openly and auditably *inside the committed action*, exactly as
`PRD_commit_reveal.md` §2.2 (D-66/SEC-07) specifies, and rule 15's own sanction is
audit-shaped. What is actually wrong is smaller and entirely fixable: **dead code carrying a
docstring that misdescribes the design**, a **stale PRD sentence** that contradicts the
current one, and a **capture claim that is derived rather than transmitted** — compliant
with `RULES.md` as worded, but one book line away from a fair question.

**Fix shape (three tasks).**

1. `strategy/deception.py` — remove `declare_truthfully` and the now-unreachable
   `ClaimKind.BARRIER`/`CAPTURE` template rows and prompt branches, OR keep them with a
   docstring that states plainly they are reserved and unused. Prefer removal: the
   enforcement that matters lives in `DeceptionPlan.__post_init__` and is untouched either
   way. **Edit the three call-site tests in this same task, before running anything** —
   `test_bluff_property.py:15` imports the symbol at module level (with uses at `:78-79`),
   so a removal that lands ahead of the test edit is an `ImportError` at collection that
   fails the whole `tests/unit/services/` directory. Also re-point `test_bluff.py:177` and
   `test_bluff_prompt.py:132-133`. Re-specify what each test was really pinning (a TRUTH
   plan for a non-LOCATION kind is still constructible via `DeceptionPlan` directly, and
   `__post_init__` still rejects a LIE for those kinds) — never silently drop the case.
   Gate the task on `uv run pytest tests/unit/services/ -q` before the suite-wide run, and
   record the rules reasoning in `docs/PRD_deception.md` so no future reader re-opens it.
2. Docs — append a dated superseded-by note to `docs/PRD_mcp_transport.md:65` pointing at
   `PRD_commit_reveal.md` §2.2 (D-66/SEC-07). Append, never rewrite: the
   `deferred-items.md` correction style.
3. Capture Claim (the de-risk) — send the existing `GAME_OVER` envelope from the capturing
   side on the capturing turn, driven by the SAME resolved outcome the ledger commits, so
   the transmitted claim and the audited record cannot disagree. No new message type, no new
   tool, no new number. If execution finds the send cannot be made without inventing
   protocol, STOP and record it as a deferred item with the measurement — do not improvise a
   new envelope to satisfy a book line that `RULES.md` does not require.

**Non-goals.** No change to `DeceptionPlan.__post_init__` or to any rules-16/22 enforcement.
No new `MessageType`. No barrier-envelope revival — D-66/SEC-07 moved it into the commit
deliberately and that decision stands. No change to how capture is RESOLVED, only to whether
it is announced.
