    GATE: this task may only be written after Tasks 1-2 are green. Shipped alone it turns

    `audit.audit_peer_records(..., *, expected_game_id: str | None = None,
    forbidden_role: str | None = None)` — both default None (check skipped), so every
    existing test and fixture is untouched.

    **Placement is exact, not approximate.** Insert the state checks in `_audit_one`
    IMMEDIATELY AFTER the `commit_pack.verify_reveal` call (:58) and BEFORE the
    `turn not in observed_reveals` trailing-commit early return (:62). Placing them after
    :62 would let a replayed record take the trailing-commit exemption — `matched=True` —
    and skip the state check entirely, which is the exact shape of the bug 06-05 already
    fixed once. Read `entry["payload"]["state"]` through `StateRecordKey`, never bare
    strings. A missing or malformed `state` key is a mismatch with a named detail, never a
    KeyError: `_audit_one` runs against peer-supplied data.

    The three checks, and the reasoning for each shape — put this in the source, not only
    here, because the shapes are the whole point:

    1. `state.turn == entry["turn"]` — ALWAYS enforced, no parameter. Free and safe:
       `_audit_one:56` already forces `entry["turn"]` into OUR numbering, and
       `commit_own_action` passes one `turn` to both the record and the append, so it holds
       for every honest ledger by construction. Closes the replay-across-turns variant.

    2. `state.role != forbidden_role` — NOT an equality check against our expected token.
       `state.role` is the PEER's own state-record content; book Sec5.3.1 shares the recipe,
       not the contents, and this repo alone carries two role vocabularies (`opponent_role`
       -> police/thief, `engine_agent` -> cop/thief). An honest opponent writing `"cop"`
       would be technically-lost by an equality check — the exact false-accusation trap
       06-05 recorded as deliberately declined. Anchoring on what must NOT appear keeps the
       property and imposes nothing: `forbidden_role=ctx.role` on the peer direction (a peer
       record claiming to have been written by US is a replay of our own commits, which every
       FINAL_REVEAL makes available), and `forbidden_role=opponent_role(ctx.role)` on the self
       direction. Symmetric, one parameter, no special-casing — the property `audit.py`'s
       docstring already prizes.

    3. `state.game_id == expected_game_id` — enforced only where AGREEMENT is demonstrable.
       `run_final_audit` supplies it for the peer direction ONLY when
       `ctx.negotiated_game_id is not None and ctx.game_uid == ctx.negotiated_game_id` —
       i.e. THIS side adopted the peer's OWN published id, so the peer's own records must
       carry it, whatever its implementation. That is true for the thief under D-61 and false
       for the police, which is correct: the police has no evidence the peer adopted anything.
       Gating on mere PRESENCE would be wrong — a symmetric honest opponent that publishes
       its id and keeps it would be accused on turn 1 of every game we play as police. The
       self direction always passes `expected_game_id=ctx.game_uid` (our own ledger certainly
       carries it). State plainly in the source: an attacker can opt out of the cross-game
       check by publishing no game_id at handshake; that is the price of not accusing honest
       strangers, and checks 1 and 2 still bind every record to a real turn and a real writer.
  </action>
