# 05-14 — the hint channel is correct on every supported path

**Gap (verify-work Round 2, 2026-08-16, HEAD `bcc04bf`).** G3 and G4 are genuinely closed —
inbound hints are logged before the drop guard, and the live round shows the responder going
from **0-of-5** decodes to **4-of-5**. Three residuals survived the adversarial pass, one of
them a correctness bug that 05-06 introduced while fixing G4.

**The one that matters.** Widening the receive window was necessary and right, but
`_buffer_if_not_older` only ever compares against the hint currently in the buffer, and
decode *pops* that buffer. A hint re-sent for turn N-1 after a pop therefore sails through
the wider window and is decoded twice — feeding the same evidence into `observe_reliability`
and the belief update a second time. The pre-05-06 guard dropped it as stale; nothing does
now. `test_hint_freshness.py:42-58` covers two arrivals with no pop between them, which is
exactly the case that still passes.

**Fix shape (three tasks).**

1. `turn_hint_buffer.py` (118/150 — room) — make "already consumed" survive the pop by
   **repurposing `ctx.pending_hints` as the consumed-marker store**: record the consumed
   `(sender, turn)` there and reject a repeat, so the window stays wide for genuinely
   late-but-fresh hints while a replay is dropped. `maybe_resolve` already clears that field
   once per resolved turn, which is exactly the marker's correct lifetime. **The trigger and
   the comparison are both load-bearing — get either wrong and the hole reopens silently.**
   The consumed state is "`incoming_hints[sender]` is ABSENT while `pending_hints[sender]`
   is PRESENT" — that pair is what distinguishes *already decoded* from *never arrived*,
   since the two are written together but only `incoming_hints` is popped by decode. Reject
   when the arriving turn is `<=` that residual stamp; do NOT reuse `_buffer_if_not_older`'s
   inclusive comparison unexamined, which would re-admit the exact repeat this task exists
   to block. Task 3's revert probe is the backstop that catches precisely this slip. **Do not touch
   `agent_context.py`, `turn_resolve.py`, or `tests/unit/test_turn_buffer.py`** — the field
   already exists, is already cleared at the right moment, and its four existing assertions
   become meaningful rather than vacuous once it is read. Restate the lookback derivation on
   the two unconfounded proofs, delete the `token_spend` sentence, and record
   `_HINT_LOOKBACK_TURNS` in `docs/PARAMETERS.md` as a derived protocol constant with the
   message-order argument beside it — documented, not turned into a tunable.
2. `turn_actions.py` (**143/150 — 7 lines of headroom, the tightest file in this plan**) —
   stamp `pending.turn` on the initiator branch as well, so both branches are correct on
   both protocol paths, and make the commit-reveal precondition in the `:121-126` comment
   explicit instead of assumed. Prefer editing the existing comment over adding prose. If
   the change does not fit, **split a sibling rather than compressing** (CLAUDE.md), and
   re-measure with `scripts/check_line_limit.sh` before committing.
3. Tests — a re-sent hint after a pop is decoded ONCE (revert probe: remove the consumed
   marker and the case fails); with `commit_reveal=False` both sides' outbound hint turn
   equals the turn played (revert probe: restore `ctx.state.turn` and it fails); the two
   existing window-boundary tests at `test_hint_freshness.py:124,:149` stay green unedited.

**Non-goals.** No change to the window WIDTH (05-06 derived it and the live round confirms
it). No hint-flood rate limiting — real, recorded as a residual, and it needs a new number
(rule 1). No change to decode, belief, or reliability maths. No touching the tool-layer
rejection path (`tools.py:71-86`), a separate uniform-across-message-types residual.
