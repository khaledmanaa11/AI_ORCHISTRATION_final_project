<objective>
Build the NET-06 deadline tracker: bound every wait on the opponent, retry transport
failures a configured number of times with a configured backoff, and — only when the
opponent has genuinely failed to respond within the whole budget — return a **technical
win verdict carrying measured evidence**.

Purpose: rule 6 (RULES.md) makes a deadline tracker mandatory — "system paralysis, loss on
timeout" is the sanction for its absence. D-13 fixes the policy: missed 30 s deadline →
retry N times with backoff → declare a technical win, log the evidence, end cleanly.

Two things make this plan delicate, and both are load-bearing:

1. **`MCPError` and `ToolError` mean different things** (RESEARCH Pitfall 4, verified
   against the pinned FastMCP v3.4.5 source). `MCPError` is a transport/protocol failure —
   the opponent is unreachable or blew the deadline. That is retryable and, once the budget
   is exhausted, ends in a technical win. `ToolError` is the opponent's tool *responding*
   with an application-level error (e.g. "illegal move"). Retrying that, or letting it fall
   into the technical-win path, would declare a win we did not earn. RULES.md rule 22 makes
   a false declaration an immediate disqualification with no appeal, so the except-clauses
   here are a correctness boundary, not style. The module therefore re-raises `ToolError`
   from a dedicated clause placed *before* the `MCPError` clause, so the distinction holds
   even if the exception hierarchy shifts under us.

2. **The technical win is a returned result, never a side effect.** This module decides
   "the opponent failed to respond within the allowed budget" and hands back the verdict
   plus its evidence. It does not end the game, does not score, does not touch game state,
   does not write to the event log. The 02-09 orchestrator acts on the verdict; 02-04's
   JSONL writer records it. Keeping the side effects out is what makes the whole retry
   ladder unit-testable in milliseconds.

Every number is injected. 30 s / 3 retries / 5 s backoff arrive as arguments read from
`NetworkParams` (02-01) — `timeout`, `retries` and `backoff` are required keyword-only
parameters with no default, so a caller that forgets one fails loudly instead of quietly
hardcoding a value.

  TechnicalWin/TechnicalWinReason/CallOutcome (or re-exported from verdict.py after the split)
- tests/unit/test_deadline.py — the full NET-06 suite replacing the Wave-0 stub

    class TechnicalWinReason(Enum):
        OPPONENT_UNRESPONSIVE = "opponent_unresponsive"

    class DeadlineExpired(Exception):
        """The opponent did not answer inside the allowed response deadline (NET-06)."""

    RETRYABLE_TRANSPORT_ERRORS: tuple[type[Exception], ...] = (MCPError, DeadlineExpired)
        # Exactly the two transport/deadline failure types. ToolError is deliberately
        # absent and must never be added here (RESEARCH Pitfall 4).

    @dataclass(frozen=True)
    class TechnicalWin:
        reason: TechnicalWinReason
        attempts: int            # attempts actually made (measured, not assumed)
        timeout_seconds: float   # the per-attempt deadline that was allowed
        backoff_seconds: float   # the backoff applied between attempts
        elapsed_seconds: float   # measured via the injected clock
        last_error: str          # type name + message of the final transport failure
        def as_evidence(self) -> dict: ...   # json.dumps-serializable, for 02-04's JSONL log

    @dataclass(frozen=True)
    class CallOutcome:
        value: object | None             # send()'s return value on success, else None
        verdict: TechnicalWin | None     # None on success
        attempts: int                    # attempts actually made, success or failure
        @property
        def succeeded(self) -> bool: ...  # verdict is None

    async def wait_for_opponent(queue: asyncio.Queue, *, timeout: float) -> object
        Bounds the WAIT_OPPONENT state. Returns the queued envelope, or raises
        DeadlineExpired when the deadline passes with the queue still empty.
        `timeout` is keyword-only and has NO default (QUAL-11).

      class FakeSleep:          # records what the retry ladder asked to wait, in order
          def __init__(self): self.calls = []
          async def __call__(self, seconds): self.calls.append(seconds)

      class FakeClock:          # scripted monotonic readings; deterministic elapsed
          def __init__(self, readings): self._readings = list(readings)
          def __call__(self): return self._readings.pop(0) if len(self._readings) > 1 \
                                     else self._readings[0]

      class FakeSend:           # the opponent, faked — never a socket, never a server
          def __init__(self, script): self.script = list(script); self.calls = 0
          async def __call__(self):
              self.calls += 1
              item = self.script.pop(0) if self.script else self.script_tail
              if isinstance(item, Exception): raise item
              return item
          # `script` is a list of either exception instances (raise) or values (return);
          # exhausting it repeats the last entry, so an always-failing peer is one entry.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| opponent process -> call_with_retry | The `send` callable reaches across the network to a process this agent does not control. | deadline.py -> JSONL event log | `last_error` is an attacker-influenced string (it embeds the opponent's error message) that ends up persisted and mailed. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07-01 | Repudiation | TechnicalWin evidence | mitigate | The verdict is built exclusively from measured values: `attempts` is the loop's own counter, and a test asserts it equals the number of times the fake `send` was actually invoked; `elapsed_seconds` comes from the injected clock.
