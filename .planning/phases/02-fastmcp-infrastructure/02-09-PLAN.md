<objective>
Build the per-agent orchestrator that turns Phase 2's parts into a playing agent: the turn loop
(`src/pursuit/network/orchestrator.py`), its startup/shutdown wiring
(`src/pursuit/network/agent_lifecycle.py`), the JSONL record builders
(`src/pursuit/network/turn_events.py`), the thin standalone entry point (`src/pursuit/main.py`),
and the convenience launcher (`scripts/dev_launch.py`).

Purpose: NET-04 requires a single entry point driving turn order through a state machine — and
D-01 fixes what "single" means here: **single per agent**. Each process embeds its own
orchestrator. There is no third referee process, no shared coordinator, and no shared runtime
object between the cop and the thief (NET-01, NET-02 — rule 2, information leakage, is a
disqualification). This plan is the one most at risk of quietly violating that rule, so
"the two agents share no runtime state" is an explicit, checkable acceptance criterion here,
not a footnote.

This plan **composes**; it invents nothing. Movement, capture and scoring come from
`pursuit.sdk.engine` (QUAL-01). Transitions come from 02-03. Durable logging and the watchdog
come from 02-04. Tools, the server task and the opponent client come from 02-06. The deadline,
retry/backoff and technical-win result come from 02-07. The config-hash handshake comes from
02-08. Re-deriving any of them is a QUAL-02 failure.

Output:
- src/pursuit/network/turn_events.py — pure D-11 record builders (no I/O)
- src/pursuit/network/orchestrator.py — AgentContext + the MY_TURN <-> WAIT_OPPONENT loop
- src/pursuit/network/agent_lifecycle.py — config load, wiring, handshake, clean shutdown
- src/pursuit/main.py — thin shell, coverage-omitted, standalone league entry point
- scripts/dev_launch.py — spawns the two standalone commands; not a referee
- tests/unit/test_turn_events.py, test_orchestrator.py, test_agent_lifecycle.py
</objective>

<!-- Decisions taken inside this plan's delegated discretion (CONTEXT.md: "module layout,
     naming, and file split"; "test structure and mocking approach"). State them in the SUMMARY. -->

1. **Three modules, not one — split, never compress.** The orchestrator is the largest unit in
   Phase 2 and will not fit one 150-line file honestly. The split is by responsibility, decided
   up front rather than discovered at line 151:
   - `turn_events.py` — **pure record builders** (dict in, dict out; no I/O, no numbers). ~60 lines.
   - `orchestrator.py` — **the turn loop only**: AgentContext, run_turn_loop, take_my_turn,
     await_opponent_turn, apply_role_move, first_legal_move. ~120 lines.
   - `agent_lifecycle.py` — **everything around the loop**: config load, wiring, reporter and
     freeze closures, server start, handshake, clean shutdown. ~130 lines.
   If `agent_lifecycle.py` still crosses the limit, split the closures and small helpers
   (`make_transition_reporter`, `make_freeze_handler`, `engine_agent`, `load_role`) into
   `src/pursuit/network/agent_wiring.py`. **Split. Never golf the code to fit.**

2. **Import direction is one-way: `agent_lifecycle` -> `orchestrator` -> `turn_events`.**
   `AgentContext` is therefore declared in `orchestrator.py` (the consumer owns the shape it
   needs) and imported by `agent_lifecycle.py`. This avoids a circular import; do not invert it.

3. **NET-02 by construction, not by promise.** Nothing in these modules is a module-level
   mutable. Every live thing — state machine, GameState replica, queue, runtime, watchdog,
   log path, game_uid — is a field on a per-process `AgentContext` **instance**. Two contexts
   built in the same test process must be provably independent; that is a named test, not a
   comment. The two agents share a *library*; they never share an *object*.

4. **The GameState replica is not an information leak.** Each agent keeps a full local replica
   including the opponent's coordinate. That coordinate arrives **only** over the wire in a
   received Envelope, or is the agent's own move. Nothing reads the opponent's process, memory,
   config directory or log. Phase 2 is the book's open-coordinate stage; blindness and hints
   arrive in Phase 4. Say this in the module docstring so a reviewer does not have to guess.

5. **Move choice is an injected seam, and it is an algorithm.** Phase 2 has no strategy (that is
   Phase 3) but the loop needs a move. `AgentContext.choose_move` is an injected callable
   defaulting to `first_legal_move(state, agent, params)` — take the first entry of
   `engine.legal_moves(...)`, which is deterministic given the engine's fixed Direction order.
   Documented as **the Phase-3 replacement point**. It is a plain algorithm: rule 25 (never let
   the language model choose a move) is respected by construction — there is no LLM in Phase 2.
   Tests inject a scripted chooser so no test depends on the placeholder's exact choice.

6. **Phase 2 sends `type=move` only.** D-06's envelope covers barriers too, and 02-06 defines
   `receive_barrier` with a real signature (D-05), but the Phase-2 loop calls
   `engine.apply_cop_action(state, move_to, barrier_at=None, params)`. `receive_barrier` stays a
   defined-but-unexercised tool; wiring barrier envelopes is a later phase's additive change, not
   a reshaping of the protocol.

7. **Who moves first comes from the role, via the state machine.** D-12 (Phase 1) fixes the turn
   order cop-then-thief, so after the handshake the police agent attempts `HANDSHAKE -> MY_TURN`
   and the thief attempts `HANDSHAKE -> WAIT_OPPONENT`. Both edges already exist in 02-03's
   `ALLOWED_TRANSITIONS`; no table change is needed and none may be made here.

8. **Inbound timeout policy (NET-06) — and the honesty constraint.** The outgoing push is wrapped
   in 02-07's `call_with_retry(retries=net.retry_count, backoff=net.backoff_seconds)`. For the
   *inbound* wait, prefer wrapping the same way:
   `await call_with_retry(lambda: wait_for_opponent(ctx.runtime.queue, net.response_timeout), ...)`.
   Check 02-07-SUMMARY first: if `call_with_retry` only retries `MCPError` and will not retry the
   inbound timeout type, then **do not write a second retry loop here** (QUAL-02) — declare the
   technical win on the first inbound timeout and record `retries_attempted: 0` **truthfully** in
   the evidence. Rules 16/22 forbid overstating what happened in a declaration; a log that claims
   three retries that never ran is exactly that kind of false report. Whichever branch is taken,
   state it in the SUMMARY.

9. **`game_uid` is a string, not a number, so no PARAMETERS.md trace is owed.** Generated per
   process at startup with `secrets.token_hex(8)` (`secrets`, never `random` — CLAUDE.md), and
   injectable so tests are deterministic. Agreeing a *shared* uid across both peers belongs to
   the Phase-6 Step-0 declaration; Phase 2 logs each side independently.

10. **Log path.** `logs/{role}/{game_uid}.jsonl`, created with `mkdir(parents=True,
    exist_ok=True)`. `logs/` is already in `.gitignore` (verified) — do not edit `.gitignore`.
    Tests always pass `tmp_path`; no test writes into `logs/`.

11. **Files this plan must NOT touch.** `pyproject.toml`, `.gitignore`, `src/pursuit/constants.py`,
    `tests/conftest.py`, `config/*/network.json`, and every `src/pursuit/network/*.py` written by
    02-01..02-08. They belong to earlier plans. `src/pursuit/main.py` is already covered by the
    existing `[tool.coverage.run] omit = ["*/main.py", ...]` — no pyproject change is needed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| opponent process -> `receive_move` -> `ctx.runtime.queue` -> `await_opponent_turn` | The only untrusted input path in this plan. Everything crossing it is attacker-controlled: turn number, sender, and the `{x, y}` payload. 02-02's `Envelope.from_dict` validates the wire SHAPE; the SDK engine validates board legality. The orchestrator itself trusts neither and computes neither. |
| command line -> `--config-dir` -> `load_agent_config` | Operator-supplied path. Fail loud on a missing dir or a malformed role.json/network.json (house style), never fall back to a default config directory — a silent fallback could start the cop with the thief's endpoints. |
| `agent_lifecycle` -> `logs/{role}/{game_uid}.jsonl` | Local filesystem write. Path is derived from config-supplied role plus a locally generated uid, never from anything the opponent sends — otherwise a hostile `sender` string becomes a path-traversal primitive. |
| `dev_launch.py` -> two child processes | Spawn-and-wait only. No pipe carries game data between children; the only argument passed is a fixed literal config directory. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09-01 | Information Disclosure | Shared runtime state between cop and thief (rule 2 — the disqualification threat) | mitigate | No module-level mutable state in either module (AST-enforced test); every live object hangs off a per-process `AgentContext` instance; the two agents are separate OS processes sharing only an importable library. `test_two_agents_share_no_runtime_state` proves pairwise object distinctness AND dynamic independence. |
| T-02-09-02 | Spoofing | `Envelope.sender` drives which SDK call runs in `apply_role_move` | mitigate | Phase 2 has one opponent and one connection; a sender that is neither "police" nor "thief" raises ValueError in `engine_agent()` and is routed to the illegal/severity path rather than silently applied. Cryptographic sender authentication is Phase 6's commit-reveal, explicitly out of scope here. |
| T-02-09-03 | Tampering | Opponent sends an off-board or illegal `{x, y}` | accept (delegated) | The orchestrator does not validate coordinates — the SDK engine does, and its rejection semantics are already Phase-1-tested. Re-validating here would duplicate logic (QUAL-02) and create two disagreeing sources of truth. |
| T-02-09-04 | Denial of Service | Opponent goes silent mid-game (deliberate stalling) | mitigate | NET-06: every wait is bounded by `response_timeout` from config; retry/backoff per D-17; then a technical win with logged evidence and a clean exit. `test_silent_opponent_produces_a_technical_win` wraps the call in an outer `asyncio.wait_for` so a regression that reintroduces a hang fails the suite instead of stalling it. |
| T-02-09-05 | Denial of Service | This agent's own process freezes (deadlock, blocked loop) | mitigate | NET-07: the watchdog daemon thread from 02-04, built with the config threshold and D-18 poll interval, touched every turn; the freeze handler writes and fsyncs the incident record BEFORE the injected exit (Pitfall 6), verified by reading the record back from disk. |
| T-02-09-06 | Repudiation | A technical-win declaration that overstates what happened | mitigate | `technical_win_record` takes `retries_attempted` as an argument reporting the retries that actually ran — never a constant, never the configured maximum. | T-02-09-07 | Elevation of Privilege | `dev_launch.py` growing into a coordinator | mitigate | AST verification that it imports nothing from `pursuit`, plus a content check that it names no game object. The standalone two-terminal path is verified independently by the two `--check-config` runs, so the launcher is never on the critical path (D-02). |
| T-02-09-08 | Tampering | Port left bound after GAME_OVER, blocking the next game | mitigate | RESEARCH Open Question 2 is discharged by `test_game_over_releases_the_port`: a plain `bind()` (no SO_REUSEADDR — the strict check on Windows) on the same port must succeed immediately after `shutdown_cleanly`. |

No HIGH-severity threat is left open. The dominant risk in this plan is not a remote attacker but
