<objective>
Build the Phase-2 transport surface: `src/pursuit/network/tools.py` (the four `async def`
`@mcp.tool` handlers with real signatures and stub bodies, D-05) and
`src/pursuit/network/peer_runtime.py` (a factory-built `FastMCP` server backgrounded with
`run_async(transport="http", host=..., port=...)` alongside a `fastmcp.Client` on the same
event loop, owning the per-process `asyncio.Queue`). RED → GREEN → REFACTOR.

Purpose: this is NET-03 — one process that is simultaneously a FastMCP server and a client —
and it is the plan every later Phase-2 plan calls into. 02-08 fills the handshake body,
02-09 drives the turn loop through this runtime, 02-10 proves §10.4 criterion 1 across it.
Getting the API shape wrong here propagates into all three. Three findings from
`02-RESEARCH.md`, each verified against the pinned FastMCP **v3.4.5** source, are load-bearing
and are restated in the tasks so the executor does not "correct" them back to the stale shapes
that most public tutorials still show:

- **Pitfall 1** — `FastMCP(host=..., port=...)` raises `TypeError` in 3.4.5 (`_REMOVED_KWARGS`).
  Host/port belong to `run_async()`, at call time.
- **Pitfall 2** — a plain `def` tool body is dispatched to a worker threadpool
  (`call_sync_fn_in_threadpool`), so it cannot safely touch a main-loop `asyncio.Queue`.
  All four handlers are `async def`.
- **Pitfall 3** — `mcp.run()` wraps `anyio.run()` and must never be called from async code.
  The server runs as `asyncio.create_task(mcp.run_async(...))`.

From src/pursuit/network/envelope.py (02-02):
```python
class MessageType(Enum):
    HANDSHAKE = "handshake"
    MOVE      = "move"
    BARRIER   = "barrier"
    GAME_OVER = "game_over"

class EnvelopeKey:          # protocol-local key names — use these, never raw string keys
    TYPE = "type"
    TURN = "turn"
    SENDER = "sender"
    PAYLOAD = "payload"

@dataclass(frozen=True)
class Envelope:
    type: MessageType
    turn: int
    sender: str
    payload: dict

    def to_dict(self) -> dict: ...
    @staticmethod
    def from_dict(data: dict) -> "Envelope": ...
```
`from_dict` accepts the wire `type` as a **string only** (never a `MessageType` instance) and
fails loud in this order: non-dict data -> `TypeError`; a missing required key -> `KeyError`;
an unexpected extra key -> `ValueError`; a non-int or bool `turn` -> `TypeError`; a non-str
`sender` -> `TypeError` and a blank one -> `ValueError`; a non-dict `payload` -> `TypeError`;
an unknown `type` value -> `ValueError`. It raises those three builtin classes — it does not
raise `ToolError`. That is why `_accept` in Task 2 translates them (see below).

    def register_tools(mcp: FastMCP, queue: asyncio.Queue) -> None

      NOTE: takes no host and no port — that is the whole point of Pitfall 1.

    class PeerRuntime:
