<objective>
Build the two pure, dependency-free primitives the whole Phase-2 protocol rests on: the typed
message envelope (D-06) and the canonical-JSON config digest (D-08, D-15).

Purpose: `envelope.py` is the module that makes §10.4 gate criterion 1 — "a geometric message
sent by agent A is received and decoded correctly by agent B" — literally true, and it fixes the
message shape once so Phase 4 hints and Phase 6 commits arrive as new `MessageType` members
rather than as a protocol redesign. `config_hash.py` is the NET-09 integrity check: the digest
exchanged during the handshake that aborts a game before move 1 if the two sides are playing by
different numbers. Both are pure functions over immutable data with zero FastMCP dependency,
which is exactly why they can be built in parallel with the state machine (02-03), the event log
(02-04) and the config loader (02-01).

The single most consequential decision executed here is hashing the **canonically re-serialized**
JSON instead of the raw file bytes (RESEARCH Pattern 6, Pitfall 5). Raw-byte hashing conflates
"identical formatting" with "identical meaning": an editor re-saving one side's
`game_params.json` with different line endings or indentation would abort a perfectly legal game
on a phantom mismatch. Canonical-JSON hashing is also already this project's locked convention
for hash inputs (SEC-03, CLAUDE.md), so reusing it here means one canonicalisation exists in the
repo instead of two that can drift apart.

Output:
- src/pursuit/network/envelope.py — MessageType, EnvelopeKey, frozen Envelope + to_dict/from_dict
- src/pursuit/network/config_hash.py — canonical_json, config_digest, digests_match
- tests/unit/test_envelope.py, tests/unit/test_config_hash.py — full suites replacing Wave-0 stubs
</objective>

Ownership boundaries — deliberate, and must be stated in the module docstrings:
- `envelope.py` does NOT validate the `turn` value's range and does NOT validate that a `move`
  payload's coordinates are on the board. It validates the wire SHAPE only. Turn ordering is the
  state machine's job (02-03); board bounds are the SDK engine's job (Phase 1). Keeping range
  checks out is also what keeps envelope.py free of numeric literals.

  (different port, different opponent URL — D-04); hashing it would abort every game. Only
  `game_params.json` is the shared artifact whose identity must hold (D-15).

    from_dict(data) -> Envelope  (staticmethod):
        Validation order, each failure raising immediately with a descriptive message:
        1. not isinstance(data, dict)                      -> TypeError
        2. REQUIRED_KEYS - data.keys() non-empty           -> KeyError (name the missing keys)
        3. data.keys() - REQUIRED_KEYS non-empty           -> ValueError (name the unexpected keys)
        4. turn: isinstance(value, bool) OR not isinstance(value, int) -> TypeError
           (the bool check must come FIRST — bool is a subclass of int in Python)
        5. sender: not isinstance(value, str) -> TypeError; not value.strip() -> ValueError
        6. payload: not isinstance(value, dict) -> TypeError

           message names the offending value and lists the known members. Note MessageType("move")
           already raises ValueError for an unknown value — re-raise with a better message rather
           than inventing a different exception class.
        Then return Envelope(type=<member>, turn=..., sender=..., payload=...).

        Accept the wire `type` as a STRING only. Do not also accept a MessageType instance — one
        accepted wire form, strictly enforced, is the whole point of a fail-loud decoder.

        mismatch (QUAL-02).

        required: scoring values are ordered [cop, thief] pairs.

        data = json.loads(Path(path).read_text(encoding="utf-8"))
        return hashlib.sha256(canonical_json(data).encode("utf-8")).hexdigest()
        Let FileNotFoundError and json.JSONDecodeError propagate unchanged — fail loud, no silent
        default digest, no empty-string fallback. encoding="utf-8" is explicit on BOTH the read
        and the encode so the digest is identical on Windows and Linux regardless of locale.

        inherits the habit where it genuinely matters.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| opponent peer -> Envelope.from_dict | Every incoming message is attacker-controlled data from a process this agent does not own. from_dict is the first and only shape-validation gate before that data reaches the orchestrator. |
| filesystem -> config_digest | game_params.json is read from disk and its digest becomes the claim this agent makes about the rules it is playing by. |
| this agent's digest -> opponent's digest | The comparison that decides whether a game may legally start (NET-09, rule 11). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Tampering | Envelope.from_dict | mitigate | Strict four-key set enforcement plus per-field type checks; a mutated, truncated or extended envelope raises rather than being silently coerced into a default. The bool-before-int ordering closes the `isinstance(True, int)` gap that would otherwise let `turn: true` decode as turn 1. |
| T-02-02-02 | Tampering | game_params.json divergence | mitigate | config_digest over canonical JSON detects any semantic difference in the shared rules; 02-08 consumes it to abort before move 1 (D-15). Canonicalisation ensures the check fires on real divergence, not on formatting drift (Pitfall 5), so the control is not desensitised by false positives. |
| T-02-02-03 | Spoofing | Envelope.sender | accept | `sender` is a self-declared, unauthenticated string in Phase 2 — an opponent can claim any role. Accepted deliberately: localhost-only traffic this phase, and Phase 6's commit-reveal is the mechanism that cryptographically binds a declaration to its author. from_dict validates that sender is a non-empty string, nothing more, and must not pretend to authenticate. |
| T-02-02-04 | Denial of Service | Envelope.payload / config_digest | accept | A hostile peer could send a deeply nested or very large payload; json.loads has a recursion limit but no size cap here. Accepted for Phase 2 (localhost, trusted dev loop). Revisit in Phase 5 when the same transport is exposed through a public tunnel — flag for that phase's research pass rather than inventing a size limit now (any such limit would be an unsourced number). |
| T-02-02-05 | Repudiation | config digest claim | accept | Nothing here binds a digest to an identity or a timestamp; a peer could later deny the digest it sent. Out of scope for Phase 2 — the JSONL event log (02-04) records what was exchanged and Phase 6 adds the cryptographic binding. |
| T-02-02-SC | Tampering | uv dependencies | mitigate | This plan introduces ZERO new packages — both modules are pure stdlib (enum, dataclasses, json, hashlib, secrets, pathlib). The forbidden-import scan in Task 2 enforces that no transport library leaks into these pure modules. |

No HIGH-severity unmitigated threats. Both modules are offline, side-effect-free computation:
config_digest performs one read-only file read, envelope.py performs no I/O at all. No secrets, no
network access, no writes. The two real controls — strict envelope validation and the config
digest — are both fail-loud by construction, which is the correct posture for a protocol boundary
with an untrusted peer.
</threat_model>
