    test_move_envelope_decoded_by_peer  (GATE-1, NET-03, NET-08, D-05, D-06, D-07):

      sender = the police role string as `load_role` / the code spells it, payload = {"x": ...,
      "y": ...} with the coordinate taken from `default_params.cop_start` rather than typed in as a
      game value.

        `result = await client.call_tool("receive_move", <envelope.to_dict() shaped to the tool's

        1. The call returned an immediate ack — whatever shape `register_tools`' handlers return;
           the point is that it returned at all, without waiting on peer B's turn (D-07).
        2. Peer B's queue holds exactly one item, and peer A's queue is still empty — the message
           travelled one way only.
        3. Decoding that queued item with `Envelope.from_dict` (or asserting it is already an
           `Envelope`, per 02-06's design) reconstructs peer A's envelope: `decoded == sent`, and
           field by field `decoded.type is MessageType.MOVE`, `decoded.turn == sent.turn`,
           `decoded.sender == sent.sender`.

           `isinstance(v, int) and not isinstance(v, bool)`. This guards against a silent
           str/float coercion in the transport, which would satisfy a lazy equality assertion while
           corrupting the geometry.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process -> peer tool surface | Gate tests call `receive_move` / `handshake` / `game_over` with crafted arguments through the in-memory client. The test IS the untrusted caller here — that is the point: it exercises the same entry the opponent will use. |
| test process -> filesystem | Every JSONL log and incident record written by a gate test goes under `tmp_path`. The repo's real log location must never be written by the suite. |
| Task 4 -> OS / network | Task 4 is the only place in this plan that binds a port and spawns processes. It runs outside pytest, is preceded by a `--check-config` pre-flight, is time-bounded, and terminates both children. |
| gate test -> production module | Tests may read and drive production modules; they may never edit them. 02-04/06/07/08/09 own their source; a gate that "fixes" the code it audits is worthless. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10-01 | Information Disclosure | Gate tests hold both agents' state in one pytest process | accept, bounded | The suite is a test harness, not an agent. NET-02 is enforced on the *shipped objects* (distinct runtimes, queues, state machines, logs), which `test_two_runtimes_share_no_runtime_state` asserts directly. No production path constructs both sides — only `tests/integration/conftest.py` does, and `src/pursuit/main.py` is asserted to hardcode no config root. |
| T-02-10-02 | Repudiation | A gate test whose name overstates what it asserts | mitigate | Every gate module carries a LIMITATION docstring; the in-memory transport is never described as "over localhost"; Task 4 records real-process evidence separately, and the SUMMARY states explicitly which claim comes from which. |
| T-02-10-03 | Tampering | A test weakened to go green against a real defect | mitigate | <interface_binding_protocol> forbids inventing an API or re-implementing production logic in a test; a missing seam is a reportable gate failure. Task 3 asserts zero skips — a quietly skipped gate test cannot pass as a passing one. |
| T-02-10-04 | Denial of Service | Watchdog thread or pending asyncio task leaking into the rest of the suite | mitigate | The freeze test drives `Watchdog.check_once` with an injected clock instead of racing the daemon thread; any thread that is `start()`ed is `stop()`ped and joined; `uv run pytest tests/integration/ -q` is run twice and must give identical results. |
| T-02-10-05 | Denial of Service | Task 4's live launch hanging the executor (firewall prompt, port in use) | mitigate | `--check-config` runs first and fails fast on a config problem; the launch is wall-clock bounded, binds only the configured localhost ports, terminates both children, and treats a bind failure as recorded evidence of a partial result rather than something to retry indefinitely. |
| T-02-10-06 | Information Disclosure | Task 4 captures process output that could contain the opponent's true position or a secret | mitigate | Output goes to the scratch directory, never the repo, never committed; Task 4 scans it for a leaked opponent position (CLAUDE.md rule 3 / RULES.md rules 8-9) and for secret-shaped strings before anything is recorded in the SUMMARY. |
| T-02-10-SC | Tampering | uv dependencies | mitigate | This plan adds no package. `fastmcp` and `pytest-asyncio` were added and audited by 02-00; the `rglob('requirements*.txt')` check re-confirms uv remains the sole package manager (QUAL-13). Standing slopcheck entry retained per GSD policy. |

No HIGH-severity threats: this plan writes only test code and runs one bounded, localhost-only
process launch. Its principal risk is not a security failure but an *epistemic* one — a gate that
claims more than it proves — which T-02-10-02 and T-02-10-03 address directly.
</threat_model>
