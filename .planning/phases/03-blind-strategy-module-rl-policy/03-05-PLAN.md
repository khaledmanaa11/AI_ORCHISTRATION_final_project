<objective>
Define what the agent considers "a state", and the table that remembers it. These two modules
decide whether the phase converges at all: an encoding that is too rich produces a table where
every key is unvisited (so the policy is permanently the fallback), and a table that does not
round-trip through JSON produces a training run whose result silently evaporates on load.

The encoding is fully specified by locked decisions — absolute (own, target) pair (D-04),
agent-relative blocked-direction bitmask plus barriers-used count (D-05), bucketed turn phase
(D-06). This plan implements exactly that and tests the two failure modes that would otherwise
pass review: the barrier bitmap creeping into the key, and a save/load cycle losing visit counts.

Output: `encoding.py`, `qtable.py` and their tests. No policy logic — 03-06 uses these.
</objective>

      turn_bucket(turn_index, params) -> int
      blocked_mask(state, cell, agent, params) -> int

    The key is a canonical string with a documented, fixed field order and separator. Choose a

    becomes garbage while still loading successfully, which is the worst possible failure shape.

  <action>
    Tests first. Then a `QTable` class:

      get(key, action) -> float          # unseen defaults to 0.0
      set(key, action, value) -> None
      bump_visit(key) -> None ; visits(key) -> int
      best_action(key) -> int            # deterministic tie-break, documented
      save(path) -> None ; load(path) -> QTable   (classmethod)

    Persistence is JSON (D-02) with a top-level `version` field and a schema that keeps values
    and visit counts together per key. Never pickle.

    **Durable save** (D-15, D-24). `os.replace` alone is **not** sufficient here — on Windows it
    maps to `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`, which is not guaranteed atomic and can fall
    back to a copy, and directory `fsync` is unavailable. The sequence is:

      1. write to a temp file **in the same directory**, `flush()`, `os.fsync(fd)`
      2. rotate the current target to `<name>.prev.json` (the real protection, not fsync)
      3. `os.replace(tmp, target)`, with a bounded retry-with-backoff on `PermissionError`
         (WinError 32 — OneDrive, Defender, or an editor holding the destination open)

    `load()` validates the file and, on failure, falls back to the `.prev` generation with a
    logged warning rather than raising — a corrupt current generation must cost one checkpoint
    interval, not the whole overnight run.

    Docstring must state why: an overnight run checkpointing every few thousand episodes will be
    interrupted eventually, and this repo sits under a OneDrive-synced path where the sync
    client holds handles open and can dehydrate files (see D-22 — this is also why training
    artifacts default outside OneDrive).

    **Fail-loud load**: malformed JSON, a missing schema version, an out-of-range action index,
    or an unparseable key each raise with the offending detail. Never return a partially
    populated table and never swallow to an empty one — an empty table loads fine and plays
    like a random agent, which is exactly the failure that wastes an overnight run.

    Keep each module ≤150 lines; split the validation into a helper module if needed rather
    than compressing.
  </action>
