<objective>
STRAT-06: training is offline, a trained Q-table ships, and learning curves are instrumented
from the first run. This plan builds the machine that produces the table.

Three findings from `03-RESEARCH.md` shape it, and each overrides an earlier assumption:

1. **The reference implementation is drivable in-process** — its brains are pure, synchronous,
   stdlib-only Python, so sparring against it costs one small adapter module, not an MCP
   adapter. But its `requires-python = ">=3.13"` makes `uv add` unresolvable against our
   floor, and its Educational-Use EULA §4c forbids redistribution — while Phase 8 ships two
   *public* repos. So it is an opt-in local clone behind a config path, never vendored, never a
   submodule (D-21).
2. **The heuristic is also the eval opponent**, so weighting it heavily in the pool is training
   on the test set. Weights become 0.30/0.50/0.20 and the eval set uses held-out seeds (D-23).
3. **`os.replace` is not atomic on Windows** and this repo sits under OneDrive. Checkpoints
   rotate a `.prev` generation, retry WinError 32, and default their directory outside the
   synced path (D-22, D-24).

Output: the `training/` package. It is offline tooling — nothing under `src/pursuit/` imports it.
</objective>
