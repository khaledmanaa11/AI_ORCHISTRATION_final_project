  <action>
    Create `strategy.json` in both `config/police/` and `config/thief/`, flat JSON matching
    the `network.json` house style with a `"version": "1.00"` field.

    **The authoritative key list and values are the config table in `03-AI-SPEC.md` §5
    ("Eval Tooling" → config keys). Copy it exactly — do not re-derive or re-choose values.**
    It defines four groups: `[strategy]`, `[training]`, `[eval]`, `[monitoring]`. Realize each
    group as a nested JSON object, matching the existing `config/<role>/*.json` convention.

    Two details in that table are easy to get wrong and are load-bearing:
    - `turn_bucket_fractions` is a list of **fractions of `move_ceiling`**, never absolute turn
      indices. Absolute indices silently break if the league negotiates a different ceiling;
      fractions re-derive correctly. The bucket boundary is computed at load from
      `move_ceiling` in `game_params.json`.
    - `qtable_path` and the brain-class key are the **only** values that differ between the two
      role files. Everything else is identical.

    Do not touch `game_params.json` — its byte-for-byte identity across both roles is a Phase-2
    guarantee (NET-09). Read `move_ceiling` from it; never restate the number in strategy.json.

    **Add these `[training]` keys on top of the AI-SPEC table** — they come from `03-RESEARCH.md`
    and from the conflict rulings in `03-PLAN-OUTLINE.md`, which override the AI-SPEC where they
    disagree:
    - `artifacts_dir` — defaults to a path **outside OneDrive**, derived at load from
      `os.environ.get("LOCALAPPDATA")` (never a hardcoded absolute path in `src/`). This repo
      lives under a OneDrive-synced directory; rewriting a multi-MB table there every few
      thousand episodes produces held handles, conflict copies and dehydrated placeholders
      (D-22). Only final blessed outputs are copied into the repo's `artifacts/`.
    - `sparring_mix` — **0.30 heuristic / 0.50 past-self / 0.20 reference**, not the AI-SPEC's
      0.5/0.35/0.15. The heuristic is also the eval opponent, so weighting it above ~⅓ is
      training on the test set (D-23).
    - `pool_snapshot_every` (10000) and `pool_size` (10) — past-self pool admission and ring
      buffer, **separate from** `checkpoint_every` (5000), which is crash recovery. Two
      different concerns, two keys.
    - `selfplay_delta` (0.5) — δ-uniform past-self sampling over the newest δ fraction.
    - `alpha_floor` / `alpha_decay_episodes` — α decays alongside ε (D-25).
    - `reference_impl_path` — **empty string default**, gitignored when set. The reference
      implementation is an opt-in local clone, never vendored and never a submodule (D-21).

    Also add an `[eval]` key `eval_seed_offset` so eval start-position seeds are provably
    disjoint from training seeds (D-23).

    **Reward keys.** The AI-SPEC config table has no reward entries, but 03-08 computes a
    reward every step and QUAL-11 forbids literals. Add to `[training]`:
    `reward_capture`, `reward_survival`, `reward_step` (the small per-turn cost that stops a
    dithering policy from scoring as well as a decisive one), and `reward_barrier_gain`.
    These are the *learner's* signal and are deliberately distinct from the game's scoring
    values in `game_params.json` — note that distinction in a comment field, because reusing
    the game scores as rewards is a defensible choice but must be a stated one.

    **`[monitoring]`.** AI-SPEC §7 gives the alert thresholds as prose, not as a config table
    row (fallback-rate alert 0.35, `q_margin` alert 0.05). Transcribe them into a
    `[monitoring]` group here so §7 has somewhere to read from. Note in the summary that no
    plan in this phase consumes them yet — they are Phase-7 reporting inputs, and shipping the
    keys now is cheaper than a config migration later.

    In `constants.py`, add `StrategyKey` and `TrainingKey` string Enums with one member per
    key above, following the existing Enum style in that file. Every later plan addresses
    config through these members, never a bare string.
  </action>

    an out-of-range probability (epsilon/gamma/win-rate bar outside 0..1) raises with the
    offending key name in the message. Never default a missing value silently — a silently
    defaulted learning rate is a training run that looks fine and learns nothing.

    Keep the module ≤150 lines. If the validation grows past that, split the range checks
    into the helpers module rather than compressing the code.
