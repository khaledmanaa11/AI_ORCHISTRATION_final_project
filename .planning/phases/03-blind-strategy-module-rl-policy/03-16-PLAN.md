<objective>
The representation that replaces the tabular key. A key over absolute coordinates shares nothing
between positions, so a table trained from one start covers one reachable cone: the cop measured
**0.600 on trained start states vs 0.133 on unseen**, the top 1% of cop keys hold **53.2%** of all

**0.00000**. Features generalise where absolute keys cannot — that is the whole case for D-26, and
the sizing that follows it: 12 features × 5 actions = **~60 weights** against 1.7M table entries,
~170,000 updates per weight instead of ~6 visits per key.

chooses a move, loads a weights file, or touches config — 03-18 searches, 03-19 wires, 03-20

    **Orientation is the whole design.** Every feature is defined in **pursuer/evader** terms,
    never own/opponent, so both roles compute the *same* twelve numbers from the same state and
    differ only in their weights (ALG-COMPARISON §7 names this as the one genuinely symmetric
    recommendation). The caller maps its role onto the pair: the cop passes `pursuer=own,
    evader=believed target`; the thief passes `pursuer=believed target, evader=own`. `pursuer` and
    `evader` are explicit arguments and need not equal `state.cop`/`state.thief` — the same
    decoupling `pathfind.bfs` already documents, and the reason blind play needs no second φ.

    | # | Feature | Divisor (a derivation, not a knob) |
    |---|---|---|
    | f0 | bias = 1 | — |
    | f1 | BFS distance pursuer↔evader | board area = `board_size ** 2` |
    | f2 | Voronoi cell-count difference, evader minus pursuer | board area |
    | f3 | Voronoi **edge**-count difference, evader minus pursuer | 2 × board area (grid `E ≤ 2V`) |
    | f4 | evader legal-move count | `len(Action)` |
    | f5 | pursuer legal-move count | `len(Action)` |
    | f6 | size of the evader's free component | board area |
    | f7 | 1.0 if the evader's cell is an articulation point of the free graph, else 0.0 | — |
    | f8 | barriers remaining = `barrier_quota − state.barriers_placed` | `barrier_quota` |
    | f9 | `encoding.turns_remaining(state.turn, game_params)` | `move_ceiling` |
    | f10 | 1.0 if f1's raw distance == 1, else 0.0 | — |
    | f11 | BFS distance evader → nearest board-edge cell | board area |

    Then the whole vector, **bias included**, is divided by `params.feature_scale_divisor` (CS188
    `divideAll(10.0)`; 03-13 declared the key as an engineering default, 03-21 sets its magnitude).

    `barrier_quota`, `move_ceiling` — read from `game_params`/`constants`, never written as a
    literal and **never declared in config**.

    Contracts:
    - **"~[0,1]" means bounded magnitude ≤ 1, not non-negative.** f2 and f3 are signed differences
      in [−1, 1] by construction and must stay signed — a difference feature that cannot change
      sign is broken. Pin the bound by test; do not shift them into [0,1].
    - **Sign is pinned:** call `territory_diff(cells, evader, pursuer)` so f2/f3 are
      evader-positive for both roles. A test asserts the sign, because 03-11's library
      deliberately names no side.
    - **`cells` is the hoist.** It must be `free_cells(state, params)` for the same `state` — a
      documented precondition, not defended at runtime, so 03-18 derives once per search node
      (D-26). Mobility is `len(neighbors(cells, cell)) + 1` for STAY, which 03-11's pin test
      already proves equal to `len(get_legal_moves(...))` — a derivation of a proven identity, not
      a second move generator.
    - **f1 uses `pathfind.bfs`** — the project's single distance oracle (QUAL-02), zero new code.
      Its `agent` argument is a probe mechanic only: `get_legal_moves` differs between roles solely
      in which field supplies `pos`, and occupancy never blocks, so the distance is
      role-independent. Pass one fixed probe agent and **pin the irrelevance by test** (both probe
      agents give the same distance).
    - **f11 is the one thing `pathfind.bfs` cannot express** — nearest of many goals, not one pair.
      Write it as a private multi-source/early-exit BFS over `cells` via `neighbors`. That is one
      copy, with a proof: on a barrier-free board it must equal `min(r, c, n−1−r, n−1−c)`. **If

  <action>
    Tests first. Then `evaluate.py`:

      WeightRow = tuple[float, ...]            # length FEATURE_COUNT
      WeightTable = dict[Action, WeightRow]    # 5 rows × 12 = 60 numbers, one role's whole store
      class Aggregation(Enum): SUM, MIN
      aggregation_for(role) -> Aggregation
      evaluate(phi_vector, row, aggregation) -> float
      best_value(phi_vector, weights, aggregation) -> float
      terminal_value(outcome, role) -> float
      validate_weights(weights) -> None

    **The two roles aggregate differently and this is not cosmetic.** The cop **sums** the twelve
    weighted terms — the ordinary dot product. The thief takes their **`min`**: a reach-avoid
    worst-case margin, where safety is set by the binding term, not the average (ALG-COMPARISON §6
    item 4, after Hsu et al. arXiv:2112.12288, which backs a safety margin up with a `min`
    operator). This is the *within-node* aggregation of the 12 weighted terms only; the
    *between-node* minimax backup is 03-18's and this plan does not define it. Say so in the
    docstring so the two are never conflated.

    Contracts:
    - `WeightTable` is **60 numbers per role** — the demoted Q-table of D-26. `best_value` is
      `max` over the five action rows, and is the leaf value 03-18 calls; `evaluate` on a single
      row is what 03-20's semi-gradient update scores. Both roles' tables are separate objects
      loaded from separate files (03-20 owns the files); nothing here reads or writes a weights
      path, and nothing here initialises weights — 03-20 owns potential-based initialisation.
    - **Terminal states are scored by `terminal_value`, never by wᵀφ.** `+INF` when `outcome` is a
      win for `role`, `−INF` when a loss: thief + `Outcome.SURVIVAL` → `+INF`, which is what lets
      alpha-beta prune a proven-safe subtree; cop + `Outcome.CAPTURE` → `+INF`; the two crosses are
      `−INF`. Domain is exactly `CAPTURE` and `SURVIVAL` — the only leaves a search can reach.
      Anything else raises, naming the outcome: a silently scored `TIE` would corrupt pruning, and
      inventing a tie value would invent a number. Sentinels are named module constants
      (`math.inf`), in the style of `pathfind.UNREACHABLE`.
    - **No multiplication on the terminal path** — `inf * 0.0` is `nan`, and one `nan` silently
      defeats every comparison in the search.
    - `validate_weights` fails loud on any row whose length is not `FEATURE_COUNT` or any missing
      `Action`, naming both. `zip` truncates silently, and a silently truncated weight row is the
      same failure shape `encoding.py` already warns about: a table that loads fine and means
      nothing. 03-20 calls it **once at load**; `evaluate` validates nothing per call — that is
      the performance contract (D-26).
    - Role is the same `"cop"` / `"thief"` string the rest of the codebase already uses for
      `agent`; no new type is introduced, and `aggregation_for` is a constant map, not state.
  </action>
