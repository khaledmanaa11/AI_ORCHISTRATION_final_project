      bfs(state, start, goal, agent, params) -> tuple[int, tuple[int,int] | None]

    Breadth-first over cells, expanding via the engine's `legal_moves` so adjacency and
    barrier-blocking come from one place. Return the optimal distance and the **first step**
    along one optimal path.

    Unreachable goal: return `(UNREACHABLE, None)` where `UNREACHABLE` is a module-level
    sentinel constant (an `int` sentinel or `math.inf` — pick one and document it). This is not
    a defensive edge case: the cop has 14 barriers and walling the thief off is a legitimate
    strategy, so callers *will* hit it. It must never raise, and must never return an arbitrary
    neighbour that a caller would then walk into.

    Tie-breaking between equal-distance first steps must be deterministic — sort candidates by
    a documented, stable rule. Non-deterministic tie-breaking makes a replayed game diverge
    from its log, which matters for Phase 6/7.

    Keep the module ≤150 lines. If a `walk()` convenience (repeatedly apply `next_step`) pushes
    it over, that helper belongs in its own module rather than compressed in.

  <files>tests/unit/strategy/test_pathfind.py</files>

  <action>
    Cover, each as a named test:

    1. **Open board** — distance equals the Manhattan distance when nothing blocks.
    2. **Walk, not just measure** — repeatedly applying `next_step` from start reaches goal in
       exactly the reported number of steps. This is the STRAT-04 gate in miniature; a test
       that only checks the integer does not prove the agent *walks* anything.
    3. **Barrier pocket** — a layout where the Manhattan-nearest neighbour leads into a dead
       end and the true shortest path goes the other way. Assert the returned first step is
       *not* the Manhattan-greedy one, and that the walk still completes. Name the test so its
       intent survives: this is the case that separates a correct fallback from one that looks
       correct (D-09).
    4. **Fully walled off** — goal enclosed by barriers returns the sentinel and `None`, and
       does not raise.
    5. **Adjacent / identical cells** — distance 1 and distance 0 behave sanely, with the
       distance-0 case returning `None` as the next step rather than a self-move.
    6. **Determinism** — two calls on identical input return identical results; and where two
       first steps tie on distance, the documented rule picks the same one every time.
    7. **Termination bound** — the walk in test 2 is capped by a budget derived from
       `move_ceiling` in params, so an oscillating implementation fails loudly instead of
       hanging the suite.

    Build states via the engine's own constructors, not hand-rolled dicts, so the tests break if
    the state shape changes.
  </action>
