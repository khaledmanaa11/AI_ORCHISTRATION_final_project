**Scope note:** this phase contains **no language model**. Rule 25 / STRAT-07 forbid the LLM from

## 1. System Classification

**System Type:** Autonomous Agent — offline-trained tabular RL decision policy (not generative, not LLM-backed)

**Description:**
A per-role decision engine that, each turn, converts a local observation (own cell, a *believed*
target cell, agent-relative blocked directions, barriers-used count, bucketed turn phase) into one
of five movement actions, plus — for the cop — a separate barrier-placement decision. Moves come
from a Q-table trained offline by self-play against a sparring pool; states the table has not
learned fall back to a Bayes motion-model prior combined with a BFS distance oracle on the
barrier-aware grid. It is used by the two agent processes (`config/police/`, `config/thief/`) via a
`BrainBase` interface selected in config `[strategy]`. "Good" means: it beats the hand-written
heuristic baseline head-to-head over the eval set, and it never needs a human in the loop to walk a
shortest path to a known target.

**Critical Failure Modes:**
1. **The policy stops being the decider.** Any path where the move is chosen by something other
   than the algorithm — hardcoded scripted move, human nudge, or (from Phase 4) the LLM —
   violates STRAT-07 / rule 25 and scores zero. The move must be traceable to `_pick_move`.
2. **Q-table noise masquerading as a policy.** Acting on state keys with near-zero visit counts
   produces confident nonsense. Without the visit-count fallback trigger (STRAT-02), the agent
   plays worse than the heuristic while *appearing* trained.
3. **Fallback that dead-ends behind a barrier.** A raw Manhattan distance heuristic walks into
   barrier pockets. The fallback must use BFS on the barrier-aware grid or STRAT-04 fails in
   exactly the situations barriers were placed to create.
4. **State-space explosion.** Encoding the full 7×7 barrier bitmap (or raw turn number) makes the
   table too sparse to ever converge — every state is unvisited, so the policy is the fallback
   wearing a Q-table costume.
5. **Self-play collapse / non-stationarity.** Training only against the current self yields a
   policy tuned to one opponent that loses to the heuristic and to the league. The sparring pool
   (STRAT-06) exists to bound this.
6. **Cross-role state leakage.** A shared live Q-table object or shared game state between cop and
   thief is an information-leak disqualification (project rule 2). Separate tables, separate
   processes.

## 1b. Domain Context

**Industry Vertical:** Academic / research — multi-agent pursuit-evasion (cops-and-robbers) on a
graph, played over a peer-to-peer MCP network. Graded coursework, University of Haifa.

**User Population:** Two autonomous agent processes playing unattended league matches against
other students' agents; a course grader reading the repo, the README learning curves, and the
replay artifacts; the student operating the training runs.

**Stakes Level:** Medium — no safety or financial exposure, but **grading-critical and
adversarial**. Opponents are other teams actively trying to win, and specific behaviours are
disqualifying rather than merely low-scoring.

**Output Consequence:** Each output is a committed move (and possibly a barrier) in a real,
irreversible league game. A bad policy loses games; a *rule-violating* policy loses the project.

### Known Failure Modes in This Domain

- **Non-stationary opponent.** Both agents learn simultaneously; a policy that converges against a
  frozen opponent degrades when the opponent changes. Mitigated by the sparring pool (heuristic +
  past-self checkpoints + reference implementation).
- **Self-play collapse.** Training exclusively against the current self converges to a narrow
  equilibrium that exploits its own blind spots and transfers poorly to the league.
- **Sparse-reward credit assignment.** Capture/escape is a terminal, rare signal; without shaped
  intermediate signal or enough episodes, most state-actions never receive gradient.
- **ε decayed too fast.** Exploration collapses before the table covers the corner/edge states that
  cornering play depends on — precisely the states the absolute (own, target) encoding was chosen
  to learn.
- **Asymmetric difficulty.** Cop and thief do not converge at the same rate; a shared success
  threshold can mark one role "done" while the other is still random.
- **Overfitting to the training board.** Parameters fixed at training time (board size, barrier
  quota, turn limit) leak into the policy; if league parameters differ, the table is mis-keyed.
- **Stalling exploitation.** The thief can learn to survive to the turn threshold rather than
  evade meaningfully — legitimate under the rules, but it must be a *learned* choice the curves
  show, not an accident of reward shaping.

## 2. Framework Decision

**Selected Framework:** None — Python standard library (`dict`, `json`, `csv`, `random`,
`collections.deque` for BFS), plus **matplotlib** as a dev-only dependency for rendering the
learning-curve PNGs.

**Version:** Python ≥3.11 (project baseline); `matplotlib` pinned in `pyproject.toml` under a
dev/training extra, installed via `uv add --dev`. No new runtime dependency — `fastmcp` remains the
only runtime dep.

**Rationale:**
The action space is 5 and the state encoding is deliberately bounded (absolute (own, target) pair,
agent-relative blocked-direction bitmask, barriers-used count, bucketed turn phase). That is a
**tabular** problem — a plain `dict` keyed by a canonical state string is the correct data
structure, and the update rule is one line of arithmetic. An RL framework (Gymnasium,
Stable-Baselines3, RLlib) would add a dependency, an environment-adapter layer, and a neural
function approximator to solve a problem that does not need one — while making the Q-table opaque
instead of a diffable JSON file the grader can open. Segal's standard rewards small, readable,
dependency-light modules; the ≤150-line file limit makes a heavyweight framework actively harmful.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Gymnasium + Stable-Baselines3 | Brings a DQN/PPO stack and a torch dependency for a 5-action tabular problem; the policy stops being human-inspectable, and rule-42 learning curves become framework artifacts rather than our own instrumentation |
| Ray RLlib | Distributed-training machinery with no benefit at this scale; heavy install, hostile to the 150-line/file and coverage gates |
| PettingZoo (multi-agent env API) | Useful abstraction for multi-agent envs, but our "environment" is the existing Phase-1 SDK engine; adopting it means rewriting working, tested code to satisfy an external interface |
| NumPy-backed array Q-table | Marginal speed gain, but forces dense allocation over a sparse visited-state set and loses the human-readable JSON serialization decision locked in CONTEXT |
| Pickle for Q-table persistence | Explicitly rejected in CONTEXT — not diffable, not grader-openable, and an arbitrary-code-execution footgun on load |

**Vendor Lock-In Accepted:** No. Zero new runtime dependencies; `matplotlib` is dev/training-only
and is not imported by any code on the move-decision path.

### Entry Point Pattern
```python
class BrainBase(ABC):
    """Every strategy is selected via config [strategy] police_class/thief_class."""

    @abstractmethod
    def _pick_move(self, obs: Observation) -> Move:
        """Choose one of the 5 movement actions. The algorithm decides — never the LLM."""

    @abstractmethod
    def _decide_move(self, obs: Observation) -> Decision:
        """Movement + (cop only) barrier sub-policy. Returns the full turn decision."""


class QLearningBrain(BrainBase):
    def _pick_move(self, obs):
        key = encode_state(obs)
        if self.table.visits(key) < self.cfg.min_visits:   # STRAT-02 fallback trigger
            return self.fallback.pick(obs)
        return self.table.best_action(key)
```

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `BrainBase` | Abstract strategy interface behind config `[strategy]` | The only seam the network layer knows about (STRAT-03) |
| State key | Canonical string: (own cell, believed target cell, blocked bitmask, barriers used, turn bucket) | Every Q-table read and write |
| Believed target cell | The input contract — Phase 3 passes the *known* target, Phase 4 passes the belief map's argmax | Keeps Phase 4 from forcing a retrain |
| Visit count | Per-state-key counter stored alongside Q-values | The STRAT-02 fallback trigger |
| Sparring pool | Heuristic + past-self checkpoints + reference implementation | Every training episode picks an opponent from it |
| BFS distance oracle | Shortest-path distance on the barrier-aware grid | STRAT-04 walk, and the "Manhattan" fallback's real distance metric |
| Barrier sub-policy | Cop-only heuristic deciding whether/where to place a barrier | After `_pick_move`; keeps the Q action space at 5 |

### Common Pitfalls
1. **Using `random` where the rules demand `secrets`, or vice versa.** e-greedy exploration is
   `random` (reproducible via seed — desirable for training). Nonces in Phase 6 are `secrets`.
   Do not let a shared "rng" helper blur these.
2. **Letting the barrier bitmap into the state key.** The single fastest way to make the table
   never converge. Blocked-directions bitmask only, agent-relative.
3. **Serializing tuple keys to JSON.** JSON object keys must be strings — the encoder must produce
   a canonical string key, and round-tripping must be tested, or a saved table silently loads as a
   different (empty) table.
4. **Training on parameters that differ from match parameters.** Board size, barrier quota and
   turn limit come from `docs/PARAMETERS.md` via config; the training harness must read the same
   config the match reads, not its own defaults.
5. **Instrumenting curves "later."** Rule 42 requires learning curves; retrofitting them means
   re-running the overnight training. Instrument from the first episode of the first run.
6. **Fallback that ignores barriers.** See critical failure mode 3 — Manhattan alone is wrong.
7. **Files creeping past 150 lines.** The encoder, table, policy, fallback, BFS, and harness are
   separate modules by necessity, not by taste. Split early; the pre-commit hook is hard-enforced.

## 4. Implementation Guidance

**Model Configuration:**
No inference model. The learned artifact is a JSON Q-table per role. All hyperparameters —
alpha (learning rate), gamma (discount), epsilon schedule shape and floor, `min_visits` fallback
threshold, turn bucket boundaries, episode counts, eval-set size and win-rate threshold — are
declared in config under `[strategy]` / `[training]`. **Zero numeric literals in `src/`** (QUAL
gate). These are internal hyperparameters, not game parameters, so they are ours to choose — but
game values (board size, barrier quota, turn limits) come from `docs/PARAMETERS.md` and may never
be invented.

**Core Pattern:**
Off-policy tabular Q-learning. Per step: encode state → e-greedy action select (explore with
probability epsilon, else argmax over the 5 actions) → apply via the Phase-1 SDK engine → observe
reward → `Q[s,a] += alpha * (r + gamma * max_a' Q[s',a'] - Q[s,a])` → increment visit count.
Terminal reward on capture/escape/turn-limit; the reward function itself is config-parameterised so
shaping can be tuned without touching source.

**Tool Use:**
None external. The only integration is inward: `BrainBase` is consumed by the Phase-2 network
layer through config `[strategy]` `police_class` / `thief_class`. No API gatekeeper is needed in
this phase because there is no external call — the gatekeeper obligation arrives with the LLM in
Phase 4.

**State Management:**
Q-tables are per-role files (`qtable_police.json`, `qtable_thief.json`) loaded once at brain
construction and held **per process**. Cop and thief never share a table object, a module-level
cache, or a live game-state object — that is project rule 2, an information-leak disqualification.
Training writes checkpoints; match play loads read-only and never writes back mid-game.

**Context Window Strategy:**
Not applicable — no LLM context in this phase. The analogous bounded resource is the **state
space**, and the strategy is the encoding itself: bounding it to (49×49 positional core) ×
(direction bitmask) × (barriers-used) × (3 turn buckets) instead of the combinatorial full-board
encoding, with the visit-count threshold guarding the still-sparse tail.

## 4b. AI Systems Best Practices

> Cross-cutting patterns, answered in RL terms. LLM-specific items are marked N/A with the
> reason — Phase 4 is where they become live.

### Structured Outputs with Pydantic

No LLM output to parse, so there is no schema-retry loop. The equivalent discipline is **typed,
validated boundaries** on the decision contract and the persisted table, so a malformed Q-table or
observation fails loudly at load rather than silently degrading play:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Observation:
    own_cell: tuple[int, int]
    target_cell: tuple[int, int]      # Phase 3: known. Phase 4: belief argmax. Same contract.
    blocked_mask: int                 # agent-relative blocked directions
    barriers_used: int
    turn_index: int

@dataclass(frozen=True)
class Decision:
    move: Move
    barrier: Barrier | None = None    # cop-only; None for the thief, always
```

Validation on Q-table load: assert every key parses back to a legal state and every action index is
in range, then fail fast. A silently-empty table is failure mode 2 in disguise.
(Project convention is dataclasses + explicit validation; Pydantic is not a project dependency and
adding one for this would contradict §2.)

### Async-First Design

The decision path is **synchronous and pure** — given an observation it returns a decision with no
I/O. This is deliberate: the Phase-2 network layer is async and owns all awaiting, deadlines, and
the watchdog. Keeping the brain sync means it is trivially unit-testable, deterministic under a
seeded RNG, and cannot leak a slow call into a turn deadline. The one common mistake to avoid:
performing Q-table file I/O inside `_pick_move` — load once at construction.

### Prompt Engineering Discipline

N/A this phase — no prompts exist, and rule 25 forbids the LLM from influencing move choice. The
structural safeguard that matters now is keeping the move path free of any hook an LLM could later
be wired into: `_pick_move` takes an `Observation` and returns a `Move`, with no free-text channel
in or out. Phase 4 adds hint decoding and bluff text *around* this boundary, never through it.

### Context Window Management

N/A — see §4 "Context Window Strategy" for the state-space analogue, which is the real bounded
resource here.

### Cost and Latency Budget

No API cost. Two budgets matter instead:
- **Per-move latency** — the decision must complete well inside the turn deadline enforced by the
  Phase-2 watchdog. A dict lookup plus a bounded BFS on a 7×7 grid is microseconds; the budget is
  effectively free, but the BFS must stay bounded and must not be run per-candidate-action in a
  loop that multiplies it.
- **Training wall-clock** — the expensive budget. Hundreds of thousands of episodes, run overnight
  by explicit choice. Checkpoint on an episode interval from config so an interrupted run is never
  a total loss, and make runs resumable and seed-logged so a good curve can be reproduced.

## 5. Evaluation Strategy

> **No LLM-as-judge anywhere in this phase.** Rule 25 / STRAT-07 keep the language model off the
> move path, and no text is generated, so there is nothing for a judge model to grade. Every
> dimension below is measured by **deterministic code** — seeded games replayed through the Phase-1
> SDK engine, BFS-oracle comparisons, static import checks — or by **human inspection of the
> learning curves**. Where the generic eval playbook reaches for a judge, a computed metric replaces it.

### Statistical honesty of the E5 bar

Both arms replay the same scenarios under the same seeds, so outcomes are **paired** — gate on
McNemar's exact test over the discordant pairs and report the unpaired two-proportion z as a
conservative cross-check. At `eval_games = 200` per arm the minimum detectable difference near
p ≈ 0.5 is ≈ **0.082** (α = 0.05, one-sided). `win_rate_margin = 0.10` is therefore the *smallest*
margin this game count can distinguish from coin-flip noise; claiming a smaller one requires raising
`eval_games` (400 games → MDE ≈ 0.058). The null is **not** 50% — it is the measured
heuristic-vs-heuristic win rate for that role on the identical scenario set, because the game is not
role-symmetric. `min_win_rate_absolute` guards the degenerate case where a weak baseline makes the
margin trivially clearable.

| `[eval]` | `convergence_window` / `convergence_tolerance` | `20000` / `0.02` | E6 slope flatness |
| `[eval]` | `max_table_keys` / `fallback_rate_gate` | `250000` / `0.40` | E7 |

Game values (`board_size` 7×7, `barrier_quota` 14, `move_ceiling` 35, scoring) are **read from
`config/<role>/game_params.json`**, which mirrors `docs/PARAMETERS.md`. Nothing above alters them.

### Eval Tooling

**Primary tool: our own `pytest` suite plus a `training/evaluate.py` self-play evaluator writing
CSV. No third-party eval platform — a deliberate override, not an omission.** The GSD default
(Arize Phoenix, with RAGAS / Promptfoo / Langfuse as alternates) is **rejected here**: every one of
them instruments *LLM* traces, prompts, and token spend, none of which exist in this phase, and
adding one would violate the project's dependency discipline (`uv`-managed, minimal runtime deps,
≤150-line files, ≥85% coverage on code we own). The eval substrate is the Phase-1 SDK engine
replaying seeded games; the "traces" are CSV rows we emit ourselves.

**Setup:**
```bash
uv sync                  # pytest, pytest-cov, ruff already in [dependency-groups].dev
uv add --dev matplotlib  # curve rendering only (§3) — zero new runtime dependencies
```

**CI/CD Integration:**
```bash
# quality-gate.yml — every push/PR (fast, deterministic dimensions only)
sh scripts/check_line_limit.sh
sh scripts/check_no_llm_in_strategy.sh                      # E2 import gate
uv run ruff check .
uv run pytest tests/unit tests/integration --cov            # E1-E4, E7-E12
uv run python -m training.evaluate --games-key eval_games_ci --smoke --assert-gate

# checkpoint-promotion job (local / nightly — minutes, not seconds)
uv run python -m training.evaluate --scenarios artifacts/eval_scenarios.json \
    --out artifacts/eval/<run_id>.csv --full --assert-gate  # E5 + E6 statistical gate
```
The per-push job asserts **no regression** on the deterministic dimensions. The full 200-game
statistical gate (E5) and the curve-shape gate (E6) run in the promotion job, because what they
gate is a checkpoint, not a commit.

### Reference Dataset

There is no text dataset. The analogue is a **frozen set of seeded game scenarios** —
`artifacts/eval_scenarios.json`, committed and version-stamped — each entry holding
`{id, seed, cop_start, thief_start, preplaced_barriers, role_under_test, expected}`. Identical
scenarios and seeds are replayed against every brain and every checkpoint, so results stay
comparable across the whole phase.

**Size:** **20 scenarios** × `repeats_per_scenario = 10` opponent seeds = **200 games per arm, per
role**. Twenty is the reference-dataset floor for a production system, and crossed with the seeds it
lands exactly at the game count E5's statistics require.

**Composition:**

| Group | n | Why it is in the set |
|---|---|---|
| Normal play | 6 | Default PARAMETERS starts, varied seeds — the common path |
| Corner / edge | 3 | Cornering play is the reason the encoding keeps absolute cells |
| Barrier-pocket traps | 4 | Layouts where Manhattan-greedy dead-ends — the E4 discriminator |
| Near-capture endgames | 3 | Cop 1–2 cells away, late turn bucket |
| Turn-limit stalling | 2 | Thief at `move_ceiling − k`; stalling must be a learned choice, not an accident |
| Shortest-path walk | 2 | Frozen opponent, known target — the §10.4 / STRAT-04 gate itself |

**Labeling** — three label types, none needing a judge model:
1. **Analytic ground truth** — a BFS oracle computes the exact optimal path length and
   distance-to-target for the path and barrier-pocket groups. Fully automated and exact.
2. **Comparative label** — for the outcome groups the label *is* the baseline arm
   (`HeuristicBrain` vs `HeuristicBrain` on the identical scenario+seed). A scenario passes relative
   to the baseline, never against an invented absolute.
3. **Author-annotated expectation** — for the endgame and stalling groups the author records the
   expected outcome class (`cop_captures_by_turn_N` / `thief_survives`), reviewed once and frozen;
   changing a frozen expectation requires a commit message explaining why.

**Timeline:** the scenario file is authored in the **first** implementation task, ahead of the
training harness, so it is the regression net *during* training rather than a retrospective.

## 6. Guardrails

### Online (Real-Time — every turn, in-match, microsecond budget)

| Guardrail | Trigger | Intervention |
|---|---|---|
| Legal-move filter | Chosen move ∉ `sdk.legal_moves(state, role, params)` | **Block** — substitute the fallback's best legal move, set `guard=illegal_move` |
| Barrier quota + legality | `barriers_placed ≥ barrier_quota`, or `place_barrier` rejects the cell | **Block** the barrier (the move still proceeds), set `guard=barrier_blocked`. Rules 16/22 — never declare a placement that did not happen |
| Low-confidence router (STRAT-02) | `visits(key) < min_visits` | **Route** to the Bayes+BFS fallback. This is failure mode 2's guardrail form |
| Decision deadline | Decision wall time > `max_decision_ms` | **Abort** the search, return the already-computed BFS-greedy move, set `guard=deadline_abort` |
| Oscillation breaker | Same cell revisited ≥ `oscillation_limit` times within `oscillation_window` turns with no BFS-distance improvement | **Force** the BFS-greedy move, set `guard=oscillation` |
| Provenance assertion (rule 25) | `Decision.source ∉ {qtable, fallback}`, or the move mutated after selection | **Raise and fail loudly** — never commit an untraceable move. A crash is recoverable; a rule-25 violation is not |
| Table fingerprint | Q-table params fingerprint ≠ live `game_params.json` fingerprint | **Force fallback for the whole match** + loud warning at load (E12) |

All seven are pure in-process checks over data already in hand — no I/O, and no latency beyond a few
comparisons plus the bounded 7×7 BFS the fallback computes anyway.

### Offline (Flywheel — per checkpoint / per training run)

| Metric | Sampling Strategy | Action on Degradation |
|---|---|---|
| Win rate vs `HeuristicBrain`, per role | Full 200-game eval set per checkpoint | Below `win_rate_margin`, or not significant → **do not promote** the checkpoint |
| Fallback rate | Per eval run and per league match | Above `fallback_rate_gate` → encoding too fine or exploration too short; retrain with a longer ε schedule |
| Mean episode reward + ε | Every `curve_log_every` episodes | Flat from episode 1 → reward-shaping bug; kill the run rather than burn the night |
| Table growth vs covered fraction | Per checkpoint | Keys grow while the `visits ≥ min_visits` fraction stays flat → state explosion (FM-4); coarsen the encoding |
| Per-role asymmetry | Per eval run, cop and thief separately | One role passes and the other does not → role-specific episode budget, never a shared "done" flag |
| Win rate split by sparring opponent | Per checkpoint, per opponent type | Beats past-self but loses to heuristic/reference → self-play collapse; reweight `sparring_mix` |
| Barrier sub-policy utility | Per checkpoint, A/B with the sub-policy disabled | Negative delta → the sub-policy spends quota to lose games; revise the STRAT-05 heuristic |

## 7. Production Monitoring

"Production" here is **live league matches against other students' agents**. There is no APM stack
and none is warranted: PARAMETERS Table 18 caps the season at **10 games**, so every match is logged
in full and reviewed by hand.

**Tracing Tool:** none third-party (same override as §5). Each turn the brain appends one
fixed-schema row to an in-memory buffer, flushed to
`artifacts/matches/<game_id>_g<NN>_strategy.csv` **at game end**, plus a one-line summary into the
existing Phase-2 `event_log`. Writing never happens on the decision path, so it cannot consume the
turn deadline.

**Emitted schema — Phase 3 owns the schema, Phase 7 builds the viewer (not now):**
`schema_version, turn, own_cell, believed_target, move, source, visits, q_margin, decision_ms,
barriers_used, guard_flags`.
**Information discipline:** own local truth only. Never the opponent's true position, never any
value held by the other process — project rule 3 / book rules 8–9. Neither agent process may read
the other's CSV.

**Key Metrics to Track** (reviewed between league games):
- Win/loss per opponent and per role, plus diversity-bonus coverage
- **Fallback rate per match** — the primary off-distribution detector against unseen opponents
- Mean `q_margin` (best minus second-best Q) — confidence collapse shows here before it shows in losses
- p99 `decision_ms` against the Phase-2 turn deadline
- `guard_flags` counts — any non-zero is investigated before the next match
- Barriers used vs quota; the thief's turn-survival profile (is the stalling deliberate?)

**Alert Thresholds** (config `[monitoring]`, checked after every match):

| Signal | Threshold | Meaning / response |
|---|---|---|
| Fallback rate in a match | > `0.35` | The shipped table does not cover this opponent's play; add the match's states as new eval scenarios and retrain before the next game |
| `guard_flags` non-zero | any `illegal_move` or `provenance` flag | Stop-the-line: a real defect, fixed before the next match |
| `deadline_abort` count | > `0` in a match | Investigate the BFS bound; raise `max_decision_ms` only if the Phase-2 deadline allows |
| p99 `decision_ms` | > 50% of the turn deadline | Latency headroom gone — profile before the next match |
| Mean `q_margin` | < `0.05` | The policy is near-indifferent; treat the match as fallback-driven and discount the win |
| Loss to an opponent style the heuristic handled in offline eval | any | Replay the match's scenario offline; if it reproduces, roll back |

**Smart Sampling Strategy:** with ≤10 scored games, sampling is unnecessary — **log 100%**.
Sampling applies to *review attention*: every loss, every match with a fired guard flag, and every
match above the fallback-rate threshold gets a full offline replay, and any scenario that reproduces
the failure is promoted into `eval_scenarios.json`. That is the dataset-expansion loop.

**Rollback of a bad checkpoint:** checkpoints are immutable, named
`qtable_<role>_v<NN>_<episode>.json`, and `[strategy].qtable_path` is the promoted pointer. A table
is **frozen for the duration of a game** — never hot-swapped mid-match — and is promoted only after
passing the full E5+E6 gate. Rollback = repoint the config at the previous checkpoint and commit;
since PARAMETERS §2 rule 5 requires emailing the commit hash for every game, a rollback is
necessarily a real, traceable commit rather than a quiet file edit.
