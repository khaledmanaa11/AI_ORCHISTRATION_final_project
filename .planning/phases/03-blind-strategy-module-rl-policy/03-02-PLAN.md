<objective>
Define the seam. `BrainBase` is the only interface the rest of the system knows about, and
`build_brain` is the only way a brain comes into existence — both required by STRAT-03, which
demands the strategy module be pluggable via config `[strategy]` and separate from networking.

This plan also lays the structural defence for STRAT-07. "The algorithm chooses the move, never
the language model" is a disqualification-grade rule, and a rule that is only stated in prose
will eventually be broken by a later phase wiring an LLM in for convenience. Making the
decision path structurally unable to reach a language model — and asserting that in a test that
runs on every commit — is what turns the rule into a guarantee.

Output: `src/pursuit/strategy/{__init__,base,registry}.py` and their tests. No policy logic
yet; `QLearningBrain` and `HeuristicBrain` arrive in 03-04 and 03-06.
</objective>

    Write the tests first. Then `base.py`:

    - frozen `Observation` dataclass: `own_cell`, `target_cell`, `blocked_mask`,
      `barriers_used`, `turn_index`. Docstring on `target_cell` must state the D-11 contract
      verbatim in substance: this is a *believed* target — Phase 3 passes the known cell,
      Phase 4 passes the belief map's argmax, and the field does not change shape.
    - frozen `Decision` dataclass: `move`, `source: MoveSource`, and
      `barrier: tuple[int,int] | None = None`, with the thief-always-None rule on `barrier` in
      the docstring.
    - `MoveSource` str Enum in `constants.py`: `QTABLE`, `FALLBACK`, `HEURISTIC`. This is not
      telemetry decoration — `03-AI-SPEC.md` §5 dimensions E2 (decision provenance) and E3
      (fallback trigger correctness) assert on `decision.source`, so a move that cannot say
      where it came from is untestable against two Critical eval dimensions. Every brain must
      set it truthfully; never default it to `QTABLE`.
    - `Action` IntEnum in `constants.py` — the **canonical 5-action space**: `NORTH`, `SOUTH`,
      `EAST`, `WEST`, `STAY`, with fixed integer values. Plus
      `cell_for(action, own_cell) -> tuple[int,int]` and `action_for(own_cell, dest)`.
      This is the index `QTable.best_action` returns and `QLearningBrain.update` writes
      (03-05, 03-06), so its **order is frozen here**: renumbering it later silently
      invalidates every trained table while still loading successfully. Pin the values with a
      test.
    - `BrainBase(ABC)` with abstract `_pick_move(obs, state) -> Decision` and
      `_decide_move(obs, state) -> Decision`.

      **Both take the `GameState` as a second argument.** The `Observation` is the *encoded*
      view used for the Q-key; it deliberately does not carry the board. But every consumer
      needs the real board — `bfs(state, ...)` (03-03), `fallback.pick(..., state, ...)`
      (03-04), `choose_barrier(state, ...)` (03-07) — so the state is passed explicitly rather
      than smuggled into `Observation` (which would bloat the encoding input and invite the
      barrier bitmap back into the key, violating D-05).

      `_pick_move` returns a full `Decision` (not a bare cell) so `source` travels with the
      move; `_decide_move` calls `_pick_move` and attaches the cop's barrier. Docstring on
      `_pick_move` states that the algorithm chooses the move and the language model never
      does (rule 25 / STRAT-07).

    Keep `__init__.py` minimal — export the contracts, nothing more. Do not add convenience
    re-exports of brains that do not exist yet.
  </action>
