  <behavior>
    place_barrier(state: GameState, cell: tuple[int, int], params: GameParams) -> GameState

    Validation order (validate FIRST, mutate SECOND — Pitfall 2 prevention):

    1. Out-of-bounds check: if cell[0] < 0 or cell[0] >= params.board_size or
       cell[1] < 0 or cell[1] >= params.board_size -> return state unchanged.

    2. Cop's own cell check: if cell == state.cop -> return state unchanged.

    3. Already-barriered check: if cell in state.barriers -> return state unchanged.

    4. Quota check: if state.barriers_placed >= params.barrier_quota -> return state unchanged.

    5. Accepted: return dataclasses.replace(
           state,
           barriers=state.barriers | frozenset({cell}),
           barriers_placed=state.barriers_placed + 1,
       )

    Boundary note — do NOT add a check for cell == state.thief: placing a barrier on
    the thief's cell IS a valid placement (D-10). The barrier lands; barriers_placed
    increments; the new state is returned. The capture consequence (rule 46 / BASE-04)
    is detected by detect_capture in 01-03, not here. This boundary is intentional and
    must be reflected in the module docstring.

    D-09 note — this function is a pure placement primitive. It does not enforce the
    "one barrier per turn" constraint; that constraint is enforced by the turn
    orchestrator (01-03) which calls place_barrier at most once per cop turn.
    barrier.py has no knowledge of turns.

    No hardcoded numbers anywhere in this file. params.barrier_quota is the sole
    source of the quota value. params.board_size is the sole source of the board
    dimension for OOB checks.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Tampering | src/pursuit/shared/barrier.py (place_barrier) | mitigate | Validate all four rejection conditions (OOB, cop's own cell, already-barriered, over-quota) before any mutation; return original state on any rejection; barrier.py never mutates state in place (frozen=True GameState prevents it) |
| T-01-02-02 | Tampering | barriers_placed counter | mitigate | Counter travels inside the immutable GameState snapshot; place_barrier only increments it on accepted placements via dataclasses.replace; rejected paths return state unchanged; no code path can increment barriers_placed on a rejected call |
| T-01-02-03 | Information Disclosure | thief position in GameState | accept | Phase 1 is a single-process test harness; cop and thief are not yet separated into processes (Phase 2). place_barrier receives full GameState; this is architecturally safe until Phase 2 enforces process separation |
| T-01-02-SC | Tampering | uv dependencies | mitigate | No new packages introduced in this plan; existing pytest/ruff packages already audited in 01-RESEARCH.md Package Legitimacy Audit (all [OK]) |

No HIGH-severity threats: place_barrier is pure offline computation with no network calls,
no file I/O, no untrusted user input beyond the cell coordinate, and no secrets. The
immutable GameState pattern is the primary correctness guarantee — frozen=True ensures
place_barrier cannot accidentally mutate the input state even if the implementation has a bug.
